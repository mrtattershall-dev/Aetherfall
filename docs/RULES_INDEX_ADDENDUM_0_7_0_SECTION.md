### The index gap that the addendum said was closed, and was not

Every prior report from 0.6.24 onward carried the line *"the index gap is
still 12 cited-but-unindexed rules"*, while the entry above titled **"Adopted
2026-09-03 — nothing is left pending"** stated that AF-R-519…522, 524, 605,
709/710/711, 1009 and 1010/1011/1012 had been adopted into `RULES_INDEX.md`.

**They had not.** The addendum recorded the decision; nobody added the rows.
Measured at 0.7.0, exactly those twelve ids were cited in code — `AF-R-711`
**52 times**, the most-cited rule in the build — and present in no index.
That is the state this document exists to prevent: the handoff's own step 0
("diff the ids cited in code against the ids in `RULES_INDEX.md`") would have
caught it at any point in the last four versions.

**Fixed in this pass.** All twelve rows are now in `RULES_INDEX.md` with
their real enforcement points. The dangerous direction is back to zero.

Two of them were enforced the whole time and simply undocumented:
`AF-R-711` gates every `AF.content` table at load, and `AF-R-709/710` are
what `AF.battle.end()` does.

## Re-audit — 0.7.0 final (measured after the vendor, recruiting, barrow and NPC work)

The 0.7.0 audit earlier in this document was taken mid-version. Re-run against
the finished build:

- **88** distinct AF-R ids cited in code (was 87 mid-version; 77 at 0.6.21).
- **21** enforced by a `refuse` / `require` call (was 20):
  `102 311 401 402 605 611 622 702 707 711 803 812 821 903 904 905 921 922 923 1010 1011`
- **0** cited in code but missing from the index — the dangerous direction has
  now been re-measured twice in one version and stayed closed.

### AF-R-611 is newly enforced

`AF-R-611` ("NPCs make places feel alive, not static quest kiosks") had been
`review`-grade since the index was written — a policy nobody could check.
`AF.content` now refuses to boot an NPC that declares no lines, and one whose
last line is conditional (an NPC that a world state could strike mute). It is
the first §7 rule with a machine check behind it.

|---|---|---|
| AF-R-601 | `AF.player.step` — phantom | movement lives in `AF.sceneKit.walk`. **Still not re-pointed in the index** (a §31 amendment, the user's call). |

| AF-R-1010 | `AF.flags` | also enforced against recruit flags and NPC line gates. |
